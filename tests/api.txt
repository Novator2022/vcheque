АПИ реализовано по стандартам HTTP REST API.
На данный момент хост http://vcheque.enginecon.ru. Рекомендуется сделать как отдельный параметр, так как хост возможно сместится на отдельный домен.
Предлагается иметь 3 параметра настроект


Авторизация:
Необходимо сделать POST запрос на url /oauth/token
Со следующими параметрами
    'grant_type' => 'password'        - константа
    'client_id' => CLIENT_ID,         - необходимо на равне с хостом ввести параметр и брать из собсвенных настроек
    'client_secret' => CLIENT_SECRET  - необходимо на равне с хостом ввести параметр и брать из собсвенных настроек
    'username' => email               - email логина в систему (выдадим)
    'password' => password            - пароль входа в систему
    'scope' => ''                     - пока не будем использовать, оставляем пустым

Чеки
Структура чека:
    "id":   идентификато чека во внутренней системе
    "created_at": "2019-08-20 11:13:09" - дата создание
    "updated_at": "2019-08-20 11:13:09" - дата последнего изменения чека
    "status": "request"                 - статус чека
    "data": {                           - Далее структура в JSON виде, у нее нет жесткой формации (что видно по XML файлу) все необходитмые поля можно добавлять здесь. Сейчас там присутсвует такие поля в таком виде
        "contractor": " ООО клиент пупкин"
        "positions": [
            {
                "nds": 20,
                "name": null,
                "amount": "1200",
                "quantity": "2",
                "nomenclature": "карандаш",
                "nomenclature_id": null
            }
            ...
        ]
    },
    "user_id": 1                        - идентификатор пользовотеля, на кого выписан чек
    "user":                             - слинкованные данные по user_id
    "organisation_id": 1,               - идентификатор организации, выдавшей чек
    "organisation":                     - подгруженная структура организации

GET /api/cheque - получение списка чеков
GET /api/cheque/{id} - получение отдельного чека по его ID
POST /api/cheque - создание чека
PUT /api/cheque/{id} - редактирование чека


Все параметры передаются как HTTP QUERY параметры
к примеру
/api/cheque?status=request - передает параметр status в запрос списка чеков (отфильтрует по этому статусу)

По остальным ресурсам аналогично, различается структура, но каждый имеет объет с именем data или meta - это JSON тип данных, для легкого расширения описания объекта, так как не известно заранее что нужно будет точно
Я так вижу, что в поля дата можно передавать и сохранять там данные о ссылке на объект в 1C и другие параметры.
